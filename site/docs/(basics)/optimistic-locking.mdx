## At a glance

| To                                     | Write                                                   |
| -------------------------------------- | ------------------------------------------------------- |
| turn locking on                        | a `lock_version INTEGER NOT NULL DEFAULT 0` column      |
| catch a save from a stale copy         | `catch (error) { if (error instanceof StaleRecord) … }` |
| catch an edit made since a form loaded | `article.assign({ lockVersion: Number(form.get(…)) })`  |
| try again with the row’s values        | `await article.reload()`, then make the change again    |
| write without checking the version     | `article.updateColumns({ … })`                          |

## Turning it on

Add a `lock_version` integer column to a table, and its Model’s records lock. Every save that writes the row checks that the row still has the record’s `lockVersion`, then adds 1 to it.

- A record with no changes sends nothing, so its version stays the same.
- A new record is saved with version 0 when it has none.
- A row whose `lock_version` is NULL reads as version 0.

## Saving a stale record

When another save changes the row after you load a record, saving your copy throws `StaleRecord`:

<include>/_excerpts/pages/optimistic-locking/examples/stale.mdx</include>

- `save()` throws, as `saveOrThrow()` does. Nothing in its write is kept, so the record’s autosaved records, counter caches, and touches roll back with it, as do the other records of a [batch](./batches).
- The error’s `record` is the stale record, and its `action` is `"update"`, `"destroy"`, or `"touch"`.
- The record keeps its changes, and the version it had.

## Writing without the check

`updateColumns`, `updateColumn`, `incrementColumn`, `decrementColumn`, and `toggleColumn` write straight to the row. They don’t check `lockVersion` or change it, and neither do counters, [counter caches](./counter-caches), `updateAll`, `deleteAll`, `touchAll`, and `Article.delete(ids)`.

:::warning[Touches change the version]
When a comment [touches](./touching) its article, the article’s `lockVersion` goes up by 1 without being checked. Someone editing the article when a comment arrives then gets `StaleRecord`. If a locked record’s children touch it often, drop their `touch`, or write them inside `noTouching`.
:::

<Callout type="info" title="Compared with Rails" icon="/ruby.svg">

Rails names the error `ActiveRecord::StaleObjectError`, and its `attempted_action` is `action` here.

Rails’ `locking_column` and `lock_optimistically = false` aren’t here: a table locks when it has `lock_version`.

When a comment touches a locked article, Rails checks the article’s version and can refuse the comment’s save. Here the touch adds 1 to the article’s version without checking it.

</Callout>
