Validations check a record before it’s saved. An invalid record isn’t saved, and its `errors` say why.

## Declaring validations

Declare validations in a Model’s `static {}` block with `this.validates`:

<include>/_excerpts/guide/validations/validates.ts</include>

Attribute names are typed, so a misspelled attribute is a compile error.

`save()` validates first, and resolves to `false` when a record is invalid. To validate without saving, call `isValid()`:

```ts
const account = Account.build(permitted);
const valid = await account.isValid();
```

:::note
`isValid()` is async, since `uniqueness` asks D1.
:::

## Available validators

| Rule           | Options                                                                                      | Error type                                     |
| -------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `presence`     | `true`                                                                                       | `blank`                                        |
| `absence`      | `true`                                                                                       | `present`                                      |
| `length`       | `{ minimum, maximum, is }`                                                                   | `tooShort`, `tooLong`, `wrongLength`           |
| `format`       | `{ with: /re/ }`, or a regex                                                                 | `invalid`                                      |
| `inclusion`    | `{ in: [...] }`, or an array                                                                 | `inclusion`                                    |
| `exclusion`    | `{ in: [...] }`, or an array                                                                 | `exclusion`                                    |
| `numericality` | `{ onlyInteger, greaterThan, greaterThanOrEqualTo, lessThan, lessThanOrEqualTo }`, or `true` | `notANumber`, `notAnInteger`, `greaterThan`, … |
| `comparison`   | `{ greaterThan, greaterThanOrEqualTo, lessThan, lessThanOrEqualTo, equalTo, otherThan }`     | `blank`, `greaterThan`, …                      |
| `acceptance`   | `true`, or `{ accept: [...] }`                                                               | `accepted`                                     |
| `uniqueness`   | `{ scope: [...], caseSensitive }`, or `true`                                                 | `taken`                                        |

Every validation runs, in the order declared, so one attribute can collect several errors. Within one `validates` call, the rules run in the table’s order. Every rule also accepts these options:

- **`allowNull`** skips the rule when the value is `null`. Otherwise `null` fails `presence`, `format`, `inclusion`, `numericality`, `comparison`, and `acceptance`, counts as length 0, and is never taken.
- **`message`** replaces the default messages from that call.
- **`if: (record) => boolean`** validates only when it returns `true`.

The default messages are in English: “can’t be blank”, “is too short (minimum is 3 characters)”, “has already been taken”, and so on. [Finding a built-in message](#finding-a-built-in-message) lists them all, and [Changing error messages](#changing-error-messages) shows how to replace them.

### Validator details

- **`presence`** fails a string that’s only whitespace. For a boolean, use `inclusion: [true, false]`, since `false` is a value.
- **`absence`** passes what `presence` fails: `null` and a string that’s only whitespace. So `false` fails it.
- **`inclusion`** is added for you by an [enum](./models#reading-and-assigning-other-values) declared `validate: true`.
- **`exclusion`** passes `null` unless the list holds it.
- **`numericality`** only accepts numbers, so a numeric string such as `"12"` is `notANumber`.
- **`comparison`** compares a number with a number, a string with a string, or a Date with a Date by its time. A bound is a value, or a function of the record (see [Comparing with another attribute](#comparing-with-another-attribute)). A `null` value, or a string that’s only whitespace, fails once, as `blank`. Comparing a number with a Date, or any two different kinds, throws `TypeError`.
- **`acceptance`** is for a box that must be ticked. It passes `true` and `"1"`, or the values you give in `{ accept: [...] }`. A checkbox left unticked sends nothing, so `null` fails too. To let `null` pass, add `allowNull: true`.
- **`uniqueness`** leaves the record itself out when updating, and never treats `null` as taken, as SQLite’s UNIQUE does. `caseSensitive: false` compares with SQLite’s `lower()`, which only lowercases ASCII letters.

<Callout type="info" title="Compared with Rails" icon="/ruby.svg">

Rails treats `false` as blank, so it passes `absence`. Here it fails `absence`, as it passes `presence`.

Rails’ `acceptance` lets `nil` pass, since its form helpers send `"0"` for an unticked checkbox. A plain HTML checkbox sends nothing, so here `null` fails.

Rails’ `confirmation` isn’t here yet.

</Callout>

:::warning[Uniqueness isn’t a guarantee]
Two requests can both check that an email is free, then both insert it. `uniqueness` gives a friendly error early, but only a UNIQUE index in the table prevents duplicates, so declare both. When the index catches a duplicate, the save throws [`RecordNotUnique`](./errors#constraint-errors).
:::

## Reading errors

A record’s `errors` hold each failed rule:

<include>/_excerpts/guide/validations/errors.ts</include>

Printing `errors`, in the console or a log, lists each failure’s attribute, type, and message. `fullMessages()` puts the attribute’s name in front, so `createdAt` reads as “Created at”. Errors on the record as a whole go on `"base"`, and read without a prefix.

An error with a number in its message, such as `tooShort`, has it in `toArray()` too:

```ts
{ attribute: "handle", type: "tooShort", message: "is too short (minimum is 3 characters)", values: { count: 3 } }
```

## Adding errors

For a rule the validators don’t cover, add errors in a `beforeValidation` or `afterValidation` callback. A record with any errors is invalid:

<include>/_excerpts/guide/validations/custom.ts</include>

`errors.add` takes the attribute, or `"base"`, then either a `type` or a message. A `type` takes its message from the Model’s `errorMessages`, as `onTheHour` does above. See [Changing error messages](#changing-error-messages). A message is used as written, and its type is `"invalid"`:

<include>/_excerpts/guide/validations/add.ts</include>

To fill in a placeholder, pass its value with the type:

```ts
account.errors.add("handle", { type: "tooShort", count: 3 });
```

To give a message and a type, pass the type as an option:

```ts
account.errors.add("handle", "is reserved", { type: "reserved" });
```

Each validation run, from `isValid()`, `save()`, or `saveOrThrow()`, starts by clearing `errors`. So an error added outside a validation callback is gone by the next save.

<Callout type="info" title="Compared with Rails" icon="/ruby.svg">

Rails’ `errors.add(:starts_at, :on_the_hour)` is `errors.add("startsAt", { type: "onTheHour" })` here, since a type and a message are both strings in TypeScript. When Rails is given a message instead, that text is the type too; here the type is `"invalid"`. Rails’ `message:` and `strict:` options and its procs aren’t here.

</Callout>

To change the message of one validation, pass `message` to `validates`. To change a message for every Model, call `this.errorMessages` in your app’s base class:

### Naming attributes

`fullMessages()` starts each message with the attribute’s name, made from the attribute itself: `createdAt` reads as “Created at”. To use another name, call `this.humanAttributeNames`, as the examples above do. Call it in the base class for every Model, or in a Model for its own attributes.

:::note
`Product.humanAttributeName("priceCents")` returns the same name, for a form’s label.
:::

In a Model, `attributes` and `humanAttributeNames` can only name the Model’s attributes, its associations, and `"base"`, so a misspelled name is a compile error. Names in the base class can be any attribute: a Model without that attribute ignores them.

### Filling in placeholders

A message can show these values:

- **`%{count}`**: the rule’s number or bound, such as the `minimum` of `tooShort` or the bound of `greaterThan`. A Date bound shows as an ISO string. A bound’s function that returns a [filtered attribute](./models#filtering-attributes)’s value shows `[FILTERED]`.
- **`%{attribute}`**: the attribute’s name, as `fullMessages()` shows it.
- **`%{model}`**: the Model’s name in words, so `BlogPost` reads as “Blog post”. It’s the class name, unless the Model sets [`static modelName`](/models#naming-models).
- **`%{value}`**: the attribute’s value. A [filtered attribute](./models#filtering-attributes) shows `[FILTERED]`.

A value passed to `errors.add` with the type, such as `count`, fills in the placeholder of the same name.

### Looking messages up

For each error, the first message found is used:

1. A message given to `validates` or `errors.add`.
2. The Model’s message for the attribute and type, then its message for the type.
3. The same for each class the Model extends, your base class included.
4. The built-in English message.

A type with no message anywhere throws a `TypeError` when the error is added.

### Finding a built-in message

Each error type has a built-in message. To replace one, use its type as the key in `errorMessages`:

| Type                       | Added by                                                   | Message                                                     |
| -------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------- |
| `blank`                    | `presence`, and `comparison` for a blank value             | can’t be blank                                              |
| `present`                  | `absence`                                                  | must be blank                                               |
| `invalid`                  | `format` and an invalid autosaved association              | is invalid                                                  |
| `inclusion`                | `inclusion`                                                | is not included in the list                                 |
| `exclusion`                | `exclusion`                                                | is reserved                                                 |
| `tooShort`                 | `length: { minimum }`                                      | is too short (minimum is `%{count}` characters)             |
| `tooLong`                  | `length: { maximum }`                                      | is too long (maximum is `%{count}` characters)              |
| `wrongLength`              | `length: { is }`                                           | is the wrong length (should be `%{count}` characters)       |
| `notANumber`               | `numericality`                                             | is not a number                                             |
| `notAnInteger`             | `numericality: { onlyInteger }`                            | must be an integer                                          |
| `greaterThan`              | `numericality` or `comparison`: `{ greaterThan }`          | must be greater than `%{count}`                             |
| `greaterThanOrEqualTo`     | `numericality` or `comparison`: `{ greaterThanOrEqualTo }` | must be greater than or equal to `%{count}`                 |
| `lessThan`                 | `numericality` or `comparison`: `{ lessThan }`             | must be less than `%{count}`                                |
| `lessThanOrEqualTo`        | `numericality` or `comparison`: `{ lessThanOrEqualTo }`    | must be less than or equal to `%{count}`                    |
| `equalTo`                  | `comparison: { equalTo }`                                  | must be equal to `%{count}`                                 |
| `otherThan`                | `comparison: { otherThan }`                                | must be other than `%{count}`                               |
| `accepted`                 | `acceptance`                                               | must be accepted                                            |
| `taken`                    | `uniqueness`                                               | has already been taken                                      |
| `required`                 | a `belongsTo` whose record doesn’t exist                   | must exist                                                  |
| `restrictDependentDestroy` | a has-one with `dependent: "restrictWithError"`            | Cannot delete record because a dependent `%{record}` exists |
| `restrictDependentDestroy` | a has-many with `dependent: "restrictWithError"`           | Cannot delete record because dependent `%{record}` exist    |

With a count of 1, the three `length` messages say “1 character”. `restrictDependentDestroy` goes on `"base"`, and `%{record}` is the association’s name in lowercase. To replace it, give both forms: `restrictDependentDestroy: { hasOne: "…", hasMany: "…" }`.

<Callout type="info" title="Compared with Rails" icon="/ruby.svg">

Rails looks messages up in its locale files, in nearly the same order: the Model’s, then its ancestors’, then the shared ones. Among the shared ones, Rails tries a message for the type before one for the attribute. Your base class tries the attribute’s first, as every class does. Active Record keeps messages on the classes instead, so a Model’s messages sit next to its validations. Their keys are Active Record’s error types, in camelCase. Rails shows “Translation missing” for a type with no message, where Active Record throws when the error is added. Messages in other languages aren’t here yet.

</Callout>
