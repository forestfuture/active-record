## Building a Relation

A query is a **Relation**, and each method that narrows, orders, or pages it returns a new one:

<include>/_excerpts/pages/querying/examples/relation.mdx</include>

- Nothing runs until you ask for results, with a method such as `toArray()`, `first()`, or `count()`.
- Relations have no `then`, so an `async` function that returns one never runs it by accident.
- Every Relation method is also a static of every Model: `User.where(…)`, `User.find(id)`, `User.count()`. `User.all()` is the Relation itself.
- A query runs on the current database: the request’s, if it was opened with `withDatabase`, or the Model’s binding. To use another, start from `db.model(User)`. See [Connections](./connecting).

## Finding records

Find one record with a finder:

<include>/_excerpts/pages/querying/examples/find.mdx</include>

- `find` throws `RecordNotFound` if the id is missing. Given several ids, it returns them in order, from one query, and throws if any are missing.
- `findBy` resolves to `null` when nothing matches, and `findByOrThrow` throws `RecordNotFound`. `findOrCreateBy` creates the record. See [Finding or creating a record](./persistence#finding-or-creating-a-record).
- `first` and `last` sort by the primary key unless the Relation has an order, and `last` reverses that order. An `sql` fragment can’t be reversed, so `last` throws `IrreversibleOrder` there. `take` reads a record with no order at all.
- `firstOrThrow`, `lastOrThrow`, and `takeOrThrow` throw `RecordNotFound` instead of resolving to `null`.
- `sole` resolves to the only matching record. It throws `RecordNotFound` when nothing matches, and `SoleRecordExceeded` when more than one does. `findSoleBy(conditions)` is short for `where(conditions).sole()`.

## Reading attributes

Read attributes without loading records with `pluck`, `pick`, and `ids`:

<include>/_excerpts/pages/querying/examples/pluck.mdx</include>

- `pluck` reads one attribute from every record, or a tuple of several.
- `pick` reads from the first record, and resolves to `null` when nothing matches.
- `ids` plucks every primary key. On a loaded association, it leaves out records you’ve built that don’t have a key yet.

## Counting and checking

Count records, or check whether any match:

<include>/_excerpts/pages/querying/examples/count.mdx</include>

- `count()` always agrees with what `toArray()` returns, even with `limit`, `offset`, or `distinct`.
- `size()`, `isEmpty()`, and `hasAny()` count records, or check for any. On a loaded association, they answer without a query.
- `hasMoreThanOne()` and `hasExactlyOne()` count no further than two records. On a loaded association, they answer without a query too.

:::tip
`exists()`, `isEmpty()`, and `hasAny()` ignore the Relation’s order, so D1 stops at the first matching row. `count()` ignores it too, unless a `limit` or `offset` needs it. D1 bills each row it reads, so checks and counts stay cheap on an ordered Relation, such as an ordered association.
:::

## Selecting attributes

Load only some attributes with `select`:

<include>/_excerpts/pages/querying/examples/select.mdx</include>

- The primary key is always loaded too, so the records can still be saved.
- Reading an attribute that wasn’t loaded throws `MissingAttribute`, including from a validator or callback. `record.hasAttribute("email")` says whether it was loaded.
- Saving a partial record writes only what changed. `reload()` loads the whole row.
- After `distinct()`, the primary key isn’t added, since it would make every row distinct, so those records can’t be saved.

Their conditions are joined with AND, and anything the argument sets, such as an order, limit, or select, replaces the receiver’s. To merge a Relation of another Model, join that Model first. See [Joins](./joins#filtering-by-a-joined-model).

## Seeing a query’s SQL

See the SQL a Relation’s `toArray()` would send, without sending it, with `toSql()`:

<include>/_excerpts/pages/querying/examples/to-sql.mdx</include>

- The values come back in `params`, apart from the SQL. Postgres numbers its placeholders: `$1`, `$2`.
- A `none()` Relation shows `1 = 0`, the condition that matches nothing.
- `toSql()` returns the real values, filtered attributes included. To see what a query sent, with those filtered, use [`onQuery`](./logging).
- Bulk writes and [batches](./batches#batching-writes) have no `toSql()`. Use [`onQuery`](./logging) to see what they sent.

<Callout type="info" title="Compared with Rails" icon="/ruby.svg">

`size()`, `isEmpty()`, and `hasAny()` are Rails’ `size`, `empty?`, and `any?`, and `hasMoreThanOne()` and `hasExactlyOne()` are `many?` and `one?`. `firstOrThrow()` is `first!`, and `findSoleBy` is `find_sole_by`. There’s no `second` or `third`. Use `offset(1).first()` instead. Rails’ `ids` gives `nil` for a built record with no key, where `ids()` leaves it out.

`merge` replaces the receiver’s order, where Rails adds the argument’s to it. `toSql()` is Rails’ `to_sql`, except that Rails writes the values into the SQL and `toSql()` keeps them in `params`.

</Callout>
