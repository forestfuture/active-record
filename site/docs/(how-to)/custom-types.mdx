## At a glance

| To                                     | Write                                                               |
| -------------------------------------- | ------------------------------------------------------------------- |
| define a type stored as a built-in one | `defineType({ storedAs: "integer", cast, serialize, deserialize })` |
| give a generated attribute the type    | `static override attributes = { priceCents: money } as const`       |
| refuse a value                         | throw from `cast`                                                   |
| query by the type’s values             | `Product.where({ priceCents: new Money(500) })`                     |

## Defining a type

Define a type with `defineType`, naming the built-in type it’s stored as. This one keeps money as whole cents in an integer column:

<include>/_excerpts/pages/custom-types/src/types/money.ts</include>

A type has three functions:

| Function      | Takes                              | Returns                            |
| ------------- | ---------------------------------- | ---------------------------------- |
| `cast`        | a value given to the attribute     | the type’s value, or throws        |
| `serialize`   | the type’s value                   | a value of the type it’s stored as |
| `deserialize` | a value of the type it’s stored as | the type’s value                   |

The attribute’s TypeScript type is what `cast` returns, so `Money` here.

:::note
None of them is called with `null`, which is always NULL.
:::

## Using a type

Give the type to a generated attribute in `static attributes`, as `Product` does:

<include>/_excerpts/pages/custom-types/src/models/product.ts</include>

Changing an attribute’s type drops its generated default, as any [override](./models#overriding-attributes) of a type does. Give it a `default` if it needs one.

A Model that declares its attributes itself, with `Model.define`, takes the type in place of a type’s name: `total: { type: money, null: false }`.

## Refusing values

Throw from `cast` for a value the type can’t hold. Assigning or permitting that value then throws a `TypeError` naming the Model and attribute, with your error as its `cause`:

<include>/_excerpts/pages/custom-types/examples/refuse.mdx</include>

The same happens when `deserialize` throws for a stored value, and when `serialize` returns a value its stored type can’t hold. For a [filtered attribute](./serialization#filtering-attributes), the error has no `cause`, since yours may show the value.

## Querying by a type

Conditions take the type’s values, and anything `cast` takes:

<include>/_excerpts/pages/custom-types/examples/query.mdx</include>

Values compare and sort as their stored values do, so money sorts by cents. A value `cast` throws for matches nothing.

## Changing values in place

A type can hold a value you change in place. This one keeps a list of sizes as text, and `Shirt` gives it to `sizes`:

<include>/_excerpts/pages/custom-types/src/types/sizes.ts</include>

Changes are found by comparing what `serialize` returns, so a size pushed onto the list is a change, and `save()` writes it:

<include>/_excerpts/pages/custom-types/examples/in-place.mdx</include>

An equal value in another object, such as a new `Money` of the same cents, isn’t a change.

<Callout type="info" title="Compared with Rails" icon="/ruby.svg">

Rails registers a type by name, with `ActiveRecord::Type.register(:money, MoneyType)`, and a Model writes `attribute :price, :money`. Here you pass the type itself, so TypeScript knows the attribute’s type. Rails’ types read the database’s values directly. Here a type is always stored as a built-in type, which reads and compares its values the same way on every database.

</Callout>
