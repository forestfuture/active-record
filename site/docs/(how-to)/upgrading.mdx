## Upgrading from 0.13 to 0.14

In 0.14, an `integer`, `real`, or `decimal` attribute reads only spaces, tabs, and line breaks around a number in text. So does a Postgres connection string’s `connect_timeout`. Its number must also fit the range libpq reads. Upgrade in one step.

### Trimming other spaces

These attributes now refuse text with a no-break space or another Unicode space around its number. A condition with that text finds nothing, and `whereNot` with it excludes nothing. On D1, a `DECIMAL` cell that holds that text fails to load. Before, each of them read the number. Call `trim()` on text before you use it as a number. It removes every Unicode space.

On Postgres, a connection string’s `connect_timeout` with one of these spaces around its number now throws `TypeError` when the Database is built. libpq refuses it too. Remove the space from the connection string. A `connect_timeout` with a `+` after its number or before its sign now throws too. Before, the `+` read as a space. Remove the `+`, so `5+` becomes `5`.

### Keeping connect timeouts in range

On Postgres, a `connect_timeout` outside -2147483648 to 2147483647 seconds now throws `TypeError` when the Database is built. libpq refuses it too. Before, a larger number waited about 24 days, and a smaller one set no limit. Use a smaller number, or `connect_timeout=0` for no limit.

## Upgrading from 0.11 to 0.12

In 0.12, a Postgres `UUID` column is a [`uuid` attribute](./attribute-types#storing-uuids). Upgrade in one step.

### Regenerating the schema

On Postgres, regenerate your schema:

```sh
npx arbor schema
```

Each `UUID` column becomes a `uuid` attribute, so a query with an id that isn’t a UUID finds nothing, where Postgres used to refuse it with an error. Assigning one throws `TypeError`. Until you regenerate the schema, `arbor schema --check` reports it as out of date. On D1, nothing changes.

## Upgrading from 0.10 to 0.11

In 0.11, the library is Arbor. Its package is `@forestfuture/arbor`, and its `arbor` command reads `arbor.jsonc`. Its behavior is the same. Upgrade in six steps.

### Replacing the package

Remove the old package, then install Arbor:

```sh
npm uninstall @forestfuture/active-record
npm install @forestfuture/arbor@^0.11.0
```

### Changing imports

Import from `@forestfuture/arbor` where you imported from `@forestfuture/active-record`. Its entries keep their names: `/d1`, `/postgresql`, `/adapter`, and `/cli`.

```ts
import { ArborError, Model } from "@forestfuture/arbor";
import { connect } from "@forestfuture/arbor/d1";
```

`ActiveRecordError` is now `ArborError`. If your Vitest config inlines the library (`server.deps.inline`), inline `@forestfuture/arbor` instead.

### Renaming the config file

Rename `active-record.jsonc` to `arbor.jsonc`, and point its `$schema` at the new package:

```jsonc
{
  "$schema": "./node_modules/@forestfuture/arbor/config-schema.json",
  "databases": {
    "DB": { "adapter": "d1" },
  },
}
```

### Running `arbor`

The command is `arbor`. `active-record` and `ffar` are gone, so change your scripts and CI:

```sh
npx arbor migrate
```

The console keeps its history in `.wrangler/arbor-history`, and on Postgres the command keeps its files in `node_modules/.cache/arbor`. The old files aren’t read, so you can delete them.

### Reinstalling the agent skill

The agent skill is now `arbor`. Install it again:

```sh
npx skills add forestfuture/arbor
```

### Regenerating the schema

Regenerate your schema:

```sh
npx arbor schema
```

Its imports change to `@forestfuture/arbor`. Until you regenerate it, `arbor schema --check` reports it as out of date.
