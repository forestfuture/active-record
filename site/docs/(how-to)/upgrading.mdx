Each section moves an app up one release. Start from the release you’re on.

## Upgrading from 0.7 to 0.8

In 0.8, a `belongsTo` requires its record, and a batch prepares its writes in a callback. Upgrade in two steps.

### Marking optional associations

Saving now fails with “must exist” when a `belongsTo` points at nothing. Add `optional: true` to each one whose foreign key can be `null`:

```ts
import { belongsTo } from "@forestfuture/active-record";

export class Category extends ApplicationRecord {
  parent = belongsTo(Category, { optional: true });
}
```

A record built through its owner’s `hasMany` or `hasOne` passes without it.

### Preparing batch writes in a callback

Pass `batch` and `db.batch` a callback that returns the writes, instead of an array:

```ts
import { batch } from "@forestfuture/active-record";

await batch((b) => [b.save(user), b.deleteAll(Post.where({ userId: user.id }))]);
```

Records’ `toSave()` and `toDestroy()`, and the `to…` methods such as `toInsert` and `toDeleteAll`, are gone. Call `b.save`, `b.destroy`, `b.insert`, and the rest instead.

## Upgrading from 0.6 to 0.7

In 0.7, the adapters ship inside `@forestfuture/active-record`, so an app on D1 installs one package. Upgrade in four steps.

### Replacing the D1 package

Remove the D1 package, then update the core:

```sh
npm uninstall @forestfuture/d1-record
npm install @forestfuture/active-record@^0.7.0
```

### Changing imports

Import what opens D1 from the core’s `/d1` entry:

```ts
import { connect, d1, withSession } from "@forestfuture/active-record/d1";
```

Everything else still comes from `@forestfuture/active-record`. If your Vitest config inlines the D1 adapter (`server.deps.inline`), inline `@forestfuture/active-record` instead.

### Writing `active-record.jsonc`

Run `init` in your project’s folder:

```sh
npx active-record init
```

It writes `active-record.jsonc`, naming each database in your Wrangler config’s `d1_databases` and its adapter:

```jsonc
{
  "$schema": "./node_modules/@forestfuture/active-record/config-schema.json",
  "databases": {
    "DB": { "adapter": "d1" },
  },
}
```

Every `active-record` command reads it. Each database’s migrations folder stays in your Wrangler config. `--adapter` is gone, and `--config` now names this file. If you used `--config` to name a Wrangler config in another folder, name it in the database’s entry with [`wranglerConfig`](./command-line#declaring-your-databases) instead.

### Regenerating the schema

Regenerate your schema:

```sh
npx active-record schema
```

Its import changes to `@forestfuture/active-record/d1`. Until you regenerate it, `active-record schema --check` reports it as out of date.

## Upgrading from d1-record 0.5 to 0.6

In 0.6, the library is two packages. `@forestfuture/active-record` is the core: Models, Relations, validations, callbacks, and associations. `@forestfuture/d1-record` is its adapter for D1. Upgrade in four steps.

### Installing both packages

Install the core beside the adapter:

```sh
npm install @forestfuture/active-record@^0.6.0 @forestfuture/d1-record@^0.6.0
```

Both packages share a version, so keep them on the same one.

### Changing imports

Import from the core everything that isn’t about D1. Import from the adapter what opens D1:

```ts
import {
  batch,
  belongsTo,
  hasMany,
  Model,
  RecordNotFound,
  withDatabase,
} from "@forestfuture/active-record";
import { connect, d1, withSession } from "@forestfuture/d1-record";
```

| Package                       | What it holds                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------ |
| `@forestfuture/active-record` | Models, Relations, `batch`, `withDatabase`, `sql`, and every error but one     |
| `@forestfuture/d1-record`     | `connect`, `Database`, `withSession`, `NoSession`, `d1`, and D1’s `QueryEvent` |

`d1-record` re-exports nothing of the core, so an import of `Model` from it fails.

### Regenerating the schema

Run the schema command under its new name:

```sh
npx active-record schema
```

The generated schema now names its adapter, `adapter: d1({ binding: "DB" })`, where it named only the binding. Your base class needs no change.

### Running `active-record`

The command is now `active-record`, or `ffar` for short. Swap it in your scripts and CI:

| Before                    | Now                           |
| ------------------------- | ----------------------------- |
| `npx d1-record schema`    | `npx active-record schema`    |
| `npx d1-record g model …` | `npx active-record g model …` |
| `npx d1-record console`   | `npx active-record console`   |

It also applies migrations through your project’s Wrangler, with `npx active-record migrate`. See [Command line](./command-line#active-record-migrate).

### Updating for the other changes

- **Write results:** `insert`, `insertAll`, `upsert`, and `upsertAll` resolve to `{ rowsAffected, rows }`, where they resolved to D1’s `meta`. `rows` holds each written row’s primary key, or the attributes its `returning` option names. Use `rowsAffected` for `meta.changes`, and `rows[0]?.id` for `meta.last_row_id`. A statement in `batch` resolves to the same.
- **The base error** is `ActiveRecordError`, where it was `D1RecordError`.
- **`toSql()` with no database:** on a Model with no generated schema, outside `withDatabase`, it throws `NoDatabase`. Use a `db` (`db.model(Post).toSql()`), or a Model built on your base class.
- **D1’s `meta`** is still on every `onQuery` event.
- **The agent skill** is now `active-record`. Install it again with `npx skills add forestfuture/active-record`.
