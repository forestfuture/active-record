## Permitting fields

Only permit the fields you want from a request:

<include>/_excerpts/guide/untrusted-input/permit.ts</include>

:::note
`permit` can also read `FormData` or `URLSearchParams`.
:::

Permitted values are cast to their attribute’s types, so `"42"` becomes `42` for an integer. [Models](./attribute-types#casting-assigned-values) lists what each type accepts. A page number from a query string can go straight to [`paginate`](./ordering-and-pagination#paginating), which casts it too.

<Callout type="info" title="Beyond Rails" icon="/ruby.svg">

Rails’ `params.permit` only filters keys. Active Record’s also casts each value, and checks that each name is an attribute.

</Callout>

## Using a schema library

If you validate requests with a schema library such as [Zod](https://zod.dev) or [Valibot](https://valibot.dev), pass the parsed result to the Model:

```ts
import { z } from "zod";

const SignUp = z.object({ email: z.string(), handle: z.string().min(3) });

const fields = SignUp.parse(await request.json());
const account = await Account.create(fields);
```

## Querying with request values

Check that a value is a string before you query with it:

<include>/_excerpts/guide/untrusted-input/null-check.ts</include>

JSON can send `null` or a list. `findBy({ token: null })` matches rows whose token is NULL, and `findBy({ token: [first, second] })` matches a row with either token.

`findOrCreateBy`, `findOrInitializeBy`, and `createOrFindBy` refuse a list. They throw a `TypeError` before they query, since their attributes become the new record’s values.

:::note
A value that can’t be cast matches nothing, so `whereNot({ id: "abc" })` excludes nothing.
:::

<Callout type="info" title="Beyond Rails" icon="/ruby.svg">

Rails’ `find_or_create_by` reads a list as `IN`, as `find_by` does. Rails doesn’t need to refuse one. A request’s params must be permitted before a model takes them, and `permit(:email)` keeps only single values.

Here, `await request.json()` is a plain object, and `permit` is up to you. So `findOrCreateBy(await request.json())` could find another user’s row. The find-or-create methods refuse a list instead. `findBy` and `where` still read a list as `IN`.

</Callout>

### Rewriting queries

Pass `rewhere` and `unscope` the attribute names and values you chose, never a request’s. They widen a query, where `where` only narrows one, so `Post.where({ published: true }).rewhere(await request.json())` would find any post the body names.

An association’s link to its owner always stays. `user.posts().rewhere({ userId: 2 })` finds nothing, since no post belongs to both users.

[Security](./security) lists what Active Record protects against, and what it leaves to your app.
