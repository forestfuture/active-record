title: Moving to Postgres
description: "Move a D1 app to Postgres with its Models and code unchanged: install pg-record, declare the database, rewrite the migrations in Postgres's types, regenerate the schema, copy the data, and switch the binding to Hyperdrive."
---

Move your app from D1 to Postgres by changing its migrations, its schema, its config, and its data. Your Models and the code that uses them stay as they are. The examples move the app from [Getting started](./getting-started).

| What changes          | How                                                       |
| --------------------- | --------------------------------------------------------- |
| Packages              | Add `@forestfuture/pg-record` and `pg`, then remove D1’s. |
| `active-record.jsonc` | New: it declares your Postgres database.                  |
| `migrations/`         | Rewritten in Postgres’s types, with the same file names.  |
| `src/db/schema.ts`    | Regenerated, so it names the Postgres adapter.            |
| Your Wrangler config  | A Hyperdrive binding in place of the D1 one.              |
| Your data             | Copied from D1 to Postgres.                               |

You’ll need `sqlite3` and `psql` on your machine to copy the data.

## Installing pg-record

Install the Postgres adapter and `pg` beside the D1 adapter:

```sh
npm install @forestfuture/pg-record pg
```

With both adapters installed, the `active-record` command asks which one you mean. Pass `--adapter pg` until you remove the D1 adapter.

These are the files `g model` writes on Postgres for the same commands. Change each type this way:

| On D1                               | On Postgres                                              |
| ----------------------------------- | -------------------------------------------------------- |
| `id TEXT PRIMARY KEY`, made in code | `id UUID PRIMARY KEY`                                    |
| `id INTEGER PRIMARY KEY`            | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `INTEGER`                           | `BIGINT`                                                 |
| `REAL`                              | `DOUBLE PRECISION`                                       |
| `DATETIME`                          | `TIMESTAMPTZ`                                            |
| `BOOLEAN`, `TEXT`                   | The same                                                 |
| `TEXT` holding JSON                 | `JSONB`                                                  |

If your `generateId` makes keys that aren’t UUIDs, keep those keys `TEXT`, and their foreign keys too.

A datetime kept as a Unix time has a `storage` override. It can stay `BIGINT`, and keep the override. To store it as `TIMESTAMPTZ` instead, add a migration that converts it after you copy the data. Then remove the override from your Model:

```sql
ALTER TABLE payments ALTER COLUMN paid_at TYPE TIMESTAMPTZ USING to_timestamp(paid_at);
```

For milliseconds, convert `to_timestamp(paid_at / 1000.0)`.

Then create the tables in your local database:

```sh
npx active-record migrate --adapter pg
```

## Regenerating the schema

Regenerate your schema from the new migrations:

```sh
npx active-record schema --adapter pg
```

Its attributes come out the same as on D1. Only its adapter changes:

```ts src/db/schema.ts
import { pg } from "@forestfuture/pg-record";

export const schema = {
  adapter: pg({ binding: "HYPERDRIVE" }),
  // …
};
```

## Copying the data

Copy your rows with this script. It exports your D1 database through Wrangler, writes each table as CSV with `sqlite3`, and loads them into Postgres with `psql`, all in one transaction:

<include meta="copy-data.sh">/_excerpts/move-to-postgres/copy-data.sh</include>

Copy your local data to your local database:

```sh
DATABASE_URL=postgres://user:password@localhost:5432/my_app sh copy-data.sh --local users posts
```

Name each table after the tables it points at, so `users` comes before `posts`.

:::note
If a table has integer keys, set its identity past the keys you copied, so the next row Postgres makes doesn’t take one of them:

```sql
SELECT setval(pg_get_serial_sequence('comments', 'id'), (SELECT max(id) FROM comments));
```

:::

## Switching the binding to Hyperdrive

Create a Hyperdrive config for your real database:

```sh
npx wrangler hyperdrive create my-app --connection-string="$PRODUCTION_DATABASE_URL"
```

Then bind it in your Wrangler config, beside your D1 binding, with the `nodejs_compat` flag `pg` needs:

<include meta="wrangler.jsonc">/_excerpts/move-to-postgres/wrangler.jsonc</include>

`npx wrangler dev` now runs your app on your local Postgres.

## Going live

:::warning[Stop writes before you copy]
A write that reaches D1 after you copy its data never reaches Postgres. Stop writes first, for example with a deploy that answers them with a 503.
:::

Then create your tables on the real database, copy the data, and deploy:

```sh
npx active-record migrate --adapter pg --remote
DATABASE_URL="$PRODUCTION_DATABASE_URL" sh copy-data.sh --remote users posts
npx wrangler deploy
```

## Removing the D1 adapter

Once your app runs on Postgres, remove the D1 adapter:

```sh
npm uninstall @forestfuture/d1-record
```

Remove the `d1_databases` entry from your Wrangler config too. The command then finds pg-record by itself, without `--adapter`.

:::tip
Your queries, validations, callbacks, and associations work the same on Postgres. A few things work differently, such as how NULLs and text sort, and `sql` fragments that use SQLite’s own functions. [Postgres](./postgres) lists each one.
:::
