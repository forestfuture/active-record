# Coding standards

Judgement calls the `code-review` skill's Standards axis checks, beyond what `vp check` enforces and what `CONTRIBUTING.md`, `docs/agents/docs-pages.md` and `docs/agents/docs-voice.md` state. Anything a tool can check belongs in a check, not here.

## Tests

- **A test's name reads as a sentence after its `describe`**, and says only what that example shows. Read "describe › test" aloud. Under `describe("none() with no database")`, write "finders and counts answer", not "answers without one": the `describe` already says it. A name stands alone: no "so do…", "too", "also" or "as well", and no opening "and" or "…". Lint flags one (`active-record/standalone-test-name`). When the word belongs to what the test shows, opt out on the line before it with the reason: `// oxlint-disable-next-line active-record/standalone-test-name -- <why>`. Lint flags an opt-out with no reason (`active-record/disable-reason`).
- **Assert results**, such as the records that come back, or the values a statement binds. Count statements through `onQuery`, and by kind with `statementKinds` (`tests/support/statement-kinds.ts`). Assert SQL text only for a safety property, such as a bound value or a quoted name, or for what only the SQL can show. Lint flags an assertion on an event's or `toSql`'s SQL (`active-record/no-sql-text`), though not a `startsWith` that picks out a kind of statement, and not in `toSql`'s own tests. When the text is what's tested, opt out on the line before it with the reason: `// oxlint-disable-next-line active-record/no-sql-text -- <why>`. Lint flags an opt-out with no reason (`active-record/disable-reason`).
- **Compare the results of a query with no order sorted, or as a set.** Each adapter returns those rows in its own order, so a positional comparison passes on D1 by chance and fails on Postgres. An order the test sets, or one the behavior promises, is compared as it is.
- **One behavior per test.** Acting on a second Model once a test has asserted, or a `DELETE` between assertions, means two tests. Reading another Model's rows to see an action's effect is fine, and so is setting up records of several Models before the first `expect`. Lint flags a second Model acted on (`active-record/one-model-per-test`), following records through `const`s; only a Model's writes and `isValid` count as acting, so a read, an association read, or a write through an association is never flagged. When acting on both is one behavior, opt out on the line before it with the reason: `// oxlint-disable-next-line active-record/one-model-per-test -- <why>`. Lint flags an opt-out with no reason (`active-record/disable-reason`).
- **A test that passes on first run is a guard.** Say so in the commit body. The `commit-msg` hook warns when a commit stages nothing outside `tests/`, adds more tests than it removes, and doesn't say "guard".
- **Wait on an event, a gate, or a polled state, never a fixed delay.** A timer passes until a slow run outlasts it. Lint flags one (`active-record/no-fixed-delay`). When the delay is what's tested, such as typing speed or a write that must not happen, or it only paces or bounds another wait, such as a poll's interval or a race's timeout, opt out on the line before it with the reason: `// oxlint-disable-next-line active-record/no-fixed-delay -- <why>`. Lint flags an opt-out with no reason (`active-record/disable-reason`).
- **Type tests see `@internal` members.** Tests compile against `src`, and only the built `.d.ts` hides them. Don't ask for a source-level `@ts-expect-error` test of one; `vp run check:public-types` covers it.

## Names and comments

- A module's first line says what it owns (lint enforces it); update it when the module gains a responsibility.
- Extract a dense pipeline into a named helper instead of casting through it.
- **Comments and test names say what the code does, not where the idea came from.** Rails is the project's starting point, not its goal, so write "start at their defaults on a load", not "as Rails does". A deliberate difference is stated as the behavior and its reason. Rails comparisons belong in the guide's Compared with Rails boxes and in `docs/contract.md`. Lint flags "Rails" in a comment in `packages/*/src/`, `packages/*/cli/` and `tests/`, and in a test's name (`active-record/say-what-it-does`). When the word belongs to what the code does, such as a test of the Compared with Rails box, opt out on the line before it with the reason: `// oxlint-disable-next-line active-record/say-what-it-does -- <why>`. Lint flags an opt-out with no reason (`active-record/disable-reason`).

## Library code

- **The library's own lookups by a record's key keep the key as stored.** A normalization runs on the conditions `where`, `findBy` and the other finders take, so a key copied from a record, such as an association's link, a preload's keys or a removal by a loaded record's key, is wrapped in `asStored(…)`. Normalizing it again could find another record's row, when that record was saved before the normalization was declared ([#354](https://github.com/forestfuture/active-record/issues/354)). Lint flags conditions with a computed key that aren't wrapped (`active-record/stored-key-lookup`), written in the call or in a `const` it names. A lookup given its conditions as a parameter is out of lint's reach, so review checks where its key comes from. When the value is the caller's, such as the ids given to `delete`, opt out on the line before it with the reason: `// oxlint-disable-next-line active-record/stored-key-lookup -- <why>`. Lint flags an opt-out with no reason (`active-record/disable-reason`).
